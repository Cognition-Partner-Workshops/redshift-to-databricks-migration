# Incident: nightly recon failure — core.orders drift (job run 762548254274974)

- **Date:** 2026-08-20 (detected ~05:16 UTC via recon-failure webhook)
- **Job:** `redshift-migration-nightly-recon` (id 220238957207364), run 762548254274974

## Root cause

Source-side data drift, not a conversion bug. 400 new orders (order_id 62798–63197,
order_ts back-dated across 2026-08-19 04:54:04 → 2026-08-20 04:47:04) were inserted
into live Redshift `core.orders` after `migration_demo.core.orders` was last synced
(target max order_ts 2026-08-20 04:39:27). Verified via LEFT ANTI JOIN on order_id
through the `redshift_src` federation catalog: exactly 400 rows present in Redshift
and missing in Databricks. `core.customers` and `core.order_items` were unaffected;
mart row-diffs were zero before remediation (both sides' marts predated the drift).

## Remediation (data catch-up only — no code changes)

1. Resynced target: `CREATE OR REPLACE TABLE migration_demo.core.orders AS SELECT * FROM redshift_src.core.orders`.
2. Rebuilt Redshift marts as `demoadmin` (`sql/etl/10`, `sql/etl/11`, unchanged legacy SQL),
   then `GRANT SELECT ON ALL TABLES IN SCHEMA mart TO PUBLIC`.
3. Rebuilt Databricks marts (`databricks/etl/10`, `databricks/etl/11` from PR #20).
