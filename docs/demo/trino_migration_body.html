What reconciliation caught

All three queries below are valid on both engines and return plausible numbers. Only comparing data, row by row, against the source exposes them.

Finding A — elapsed days vs calendar days. Trino date_diff('day', first_ts, last_ts) counts full 24-hour periods. Spark DATEDIFF counts midnight crossings. 95 of 150 customers got a different active_days. Fix: (UNIX_MILLIS(last_ts) − UNIX_MILLIS(first_ts)) DIV 86400000.
Finding B — decimal division scale. Trino keeps DECIMAL(12,2) / BIGINT at scale 2; Spark widens to scale 18 and rounds differently in 15 daily rows. Fix: cast the division and AVG results back to the source scale.
Finding C — approximate percentiles (open). Trino approx_percentile and Spark percentile_approx use different estimators, so report 22's promo ranking flips. Both engines are "correct". Decision needed: adopt exact percentile on both sides before sign-off.
